# web aesthetic craft - research

**researched:** 2026-04-16
**stream:** tinamation
**confidence:** medium (most findings verified across multiple sources; specific pixel values and timing numbers are cross-referenced)

## summary

this research covers the execution-level craft details that separate functional sites from beautiful ones, with a specific lens on portfolio sites for creative/3d artists. explored six dimensions: motion design with concrete timing values, visual hierarchy techniques, whitespace as quality signal, color strategy, intangible "feel" signals, and portfolio-specific patterns.

the dominant pattern across all sources: restraint is the differentiator. premium sites succeed not by adding more but by doing less with more intention. the best 3d artist portfolios (awwwards winners 2025) let the work be the spectacle — the chrome (navigation, transitions, type, spacing) is neutral, polished, and invisible.

a second strong pattern: motion has crossed from "decoration" to "signage." in 2026, animation serves as communication — confirming actions, teaching spatial relationships, directing attention — rather than impressing visitors. this shift is central to what separates craft from gimmick.

**key insight:** the gap between "looks designed" and "feels crafted" lives almost entirely in timing, spacing ratios, and easing curves — the things users never consciously notice but immediately feel.

## current understanding

### what exists

**motion design tooling:** framer motion (react), gsap (vanilla/react), css scroll-driven animations api (native, compositor-offloaded). three.js/webgl for 3d. the scroll-driven animations api is notable — pure css, runs off main thread, no jank.

**visual hierarchy tools:** size contrast, color contrast, spatial positioning, entry stagger, density variation. the "squint test" is a real technique: blur the page mentally and check if the most important element still reads first.

**whitespace systems:** 8px grid (multiples of 8 for all spacing) is industry-standard, popularized by material design and adopted broadly. macro whitespace (between sections) matters more than micro (between elements) for luxury signaling.

**color systems:** neutral-first palettes (warm grays, stone, charcoal) with single accent color. wcag aa = 4.5:1 contrast for body text, 3:1 for large text. for portfolio: the work itself should be the color — chrome stays near-monochrome.

**typography micro-details:** variable fonts (single file, any weight/width), optical sizing (`font-optical-sizing: auto`), `font-feature-settings` for ligatures/kerning. these are browser-supported and largely free wins.

### how it works

**timing mechanics:** the human perception threshold for "instant" is ~100ms. below that, interactions feel native. above 500ms, users register "waiting." the sweet spot for most ui animation is 150-300ms. longer durations (400-600ms) work only for page-level transitions or deliberate narrative moments.

**easing mechanics:** linear motion looks robotic. `ease-out` (fast start, slow end) is the primary curve for nearly all ui work because the deceleration reads as "arrival" and feels natural. `ease-in` is for exits. the spring curve `cubic-bezier(0.34, 1.56, 0.64, 1)` has a slight overshoot that feels energetic without being cartoonish — useful for cards and buttons.

**whitespace mechanics:** whitespace communicates market position more directly than almost any other design choice. heavy whitespace = luxury/premium, balanced whitespace = mid-tier, little whitespace = low-end. this is not metaphor — multiple brand studies confirm it. the mechanism: scarcity implies confidence. only brands that don't need to sell everything at once use space generously.

**hierarchy mechanics:** humans process visual contrast before content. a 2-3x size differential between heading and body text creates clear hierarchy; less than 1.5x collapses into ambiguity. color contrast reinforces size hierarchy but shouldn't substitute for it.

### what's interesting

the "ai-generated design" detection finding is sharp: ai design is identified not by errors but by its lack of necessity. human design feels "necessary" — every choice reflects a specific person's taste, history, cultural reference. ai design feels "inevitable" — optimized, smooth, could have been generated by anyone. the anti-pattern is uncanny not because it's broken but because it's frictionless in an inhuman way.

the argument that disney's 12 principles don't apply to ui is worth taking seriously. the one principle that universally applies: easing. everything else is context-dependent. the alternative framing is useful: ui animation is "signage," not "character acting." it should tell users where things came from, where they're going, and what changed — not entertain.

## patterns observed

### pattern 1: timing tiers

**what:** all animation durations cluster into three tiers based on function:
- micro (button press, toggle, tooltip): 80-200ms
- component (modal, drawer, card expand): 250-300ms
- macro (page transition, scroll narrative): 300-500ms

**where seen:** motion.dev docs (framer), bettermockups motion design guide, web animation best practices gist
**significance:** violating tiers is what makes animation feel wrong. a 500ms button press feels broken. a 100ms page transition feels rushed and disorienting.
**example:**
```
button hover:    200ms  ease-out
button press:    80-100ms  fast cubic-bezier
modal entrance:  250-300ms  smooth ease-out
page transition: 300-500ms  spring or ease-out
success state:   600ms  spring with overshoot (intentionally slower for celebration)
stagger offset:  50-100ms between sequential elements
anticipation:    <100ms (must be sub-threshold to feel responsive)
```

### pattern 2: easing as primary quality signal

**what:** generic `ease` or `linear` is immediately detectable as low-craft. custom cubic-bezier curves are the cheapest quality upgrade.

**where seen:** motion.dev docs, web animation best practices gist, framer academy
**significance:** a single timing curve upgrade from `ease` to a tailored bezier changes how the whole interface feels without changing a single visual element.
**example:**
```css
/* the three core curves */
--ease-spring:   cubic-bezier(0.34, 1.56, 0.64, 1);  /* buttons, cards — slight overshoot */
--ease-smooth:   cubic-bezier(0.16, 1, 0.3, 1);       /* modals, page transitions — large movements */
--ease-snappy:   cubic-bezier(0.4, 0, 0.2, 1);        /* toggles, loaders, icons */
```

### pattern 3: neutral chrome, work as color

**what:** top 3d artist portfolios consistently use near-monochrome site shells — black, white, gray — with a single restrained accent. all color impact comes from the artwork itself.

**where seen:** awwwards portfolio winners 2025 analysis, muzli top 100 portfolios, portfolio color palette research
**significance:** this is the correct strategy for tinamation specifically. the 3d renders are the visual spectacle. the site's job is to get out of the way and present them.
**example:**
```
frédéric colin (netflix/appletv+ 3d director): black-and-white, minimal, long scroll of projects
the work: full-bleed 3d renders that fill the viewport
the chrome: near-invisible, single weight of a neutral sans
```

### pattern 4: whitespace as luxury signal

**what:** spacing multiples of 8px at the micro level, but the bigger lever is macro whitespace — section padding, vertical breathing room between content blocks. premium portfolio sites use 120-240px of vertical padding around major content sections.

**where seen:** wayfair design blog (rule of 8), multiple brand strategy analyses, wcag spacing guidance
**significance:** under-spacing is the most common mistake on self-built portfolio sites. it reads as "filling the page" rather than "curating the experience."
**concrete guidance:**
```
rule of 8: all spacing is a multiple of 8px
  micro spacing:  8px, 16px, 24px (within components)
  mid spacing:    32px, 40px, 48px (between related elements)
  macro spacing:  64px, 96px, 128px+ (between sections)
body text: minimum 16px, 18px preferred
line-height: 1.5-1.7 for body, 1.1-1.2 for headings
```

### pattern 5: scroll-linked animation architecture

**what:** parallax and scroll-driven effects are high-risk for performance jank. the correct implementation: css scroll-driven animations api (compositor thread), or `transform`/`opacity` only via js with `requestAnimationFrame`.

**where seen:** chrome developer blog on performant parallaxing, logrocket on scroll-linked effects, css-tricks scroll-driven animations
**significance:** jank on scroll feels broken, even if the design intent is beautiful. performance is part of the aesthetic.
**concrete rules:**
```
- only animate: transform, opacity, filter (compositor-friendly)
- never animate: width, height, padding, margin, top, left (triggers layout)
- use css scroll-driven animations for compositor-offloaded effects
- always implement: prefers-reduced-motion media query
- parallax: max 2-3 elements per scroll zone, avoid heavy z-stacking
```

### pattern 6: typography micro-details

**what:** variable fonts + optical sizing + font-feature-settings form a three-layer upgrade that together distinguish professional from amateur typography. each is independently valuable; together they compound.

**where seen:** mdn docs, monotype optical sizing guide, css-tricks font-optical-sizing, inkbotdesign variable fonts guide
**significance:** these are mostly free wins via css — no design changes required, only technical implementation.
**concrete implementation:**
```css
/* variable font with optical sizing enabled */
body {
  font-family: 'YourFont', sans-serif;
  font-optical-sizing: auto;
  font-feature-settings: "kern" 1, "liga" 1, "calt" 1;
}

/* large headings: tighten tracking, adjust optical size */
h1 {
  font-variation-settings: 'opsz' 72;  /* optical size axis */
  letter-spacing: -0.03em;  /* -0.02 to -0.04em at display sizes */
}

/* body: open tracking, relaxed */
p {
  font-variation-settings: 'opsz' 16;
  letter-spacing: 0;
}
```

## contradictions & tensions

1. **disney principles: apply vs. don't apply**
   - view a: disney's 12 principles (squash/stretch, anticipation, staging, etc.) are foundational to understanding motion in any medium including ui
   - view b: disney principles solve for organic character movement in physical space; ui animation is "signage" not "character acting" — the principles are irrelevant or actively misleading
   - significance: both have truth. easing (slow in/slow out) universally applies. staging and secondary action apply. squash/stretch and anticipation are high-risk in ui — they can feel cartoonish at small scale. the practical resolution: use easing as gospel, treat the rest as optional tools for specific moments.

2. **motion adds delight vs. motion adds noise**
   - view a: micro-interactions and hover effects reward exploration and create emotional connection
   - view b: in 2026, users have high animation fatigue; restraint and near-zero motion is what feels premium
   - significance: both are currently winning strategies at the high end. the differentiator is intentionality: random decorative animation = noise; animation that teaches/confirms/reveals = signal. for tinamation specifically, the work IS 3d motion — too much site motion will compete with the artwork.

3. **custom cursors: craft signal vs. accessibility trap**
   - view a: custom cursors are a signature craft detail of creative/agency sites, immediately signal "this isn't a template"
   - view b: custom cursors can break accessibility, confuse users, cause performance issues, and are often the first thing designers implement when avoiding harder problems
   - significance: worth implementing only if done correctly (pointer-events passthrough, fallback for touch, reduced-motion compliant). the risk of doing it badly outweighs the reward of doing it halfway.

## open questions

1. **what is tinamation's current motion baseline?**
   - what we know: the flipbook has page-turn animation; the site uses next.js 15 with mui joy
   - what's unclear: which entry animations, hover states, and transitions currently exist; what easing curves are in use; whether prefers-reduced-motion is implemented
   - worth exploring: yes — audit current motion before adding more

2. **does the flipbook's 3d motion set an expectation that the rest of the site can't meet?**
   - what we know: awwwards 3d artist portfolios use immersive 3d throughout, not just in one feature
   - what's unclear: whether a high-craft 3d feature surrounded by a low-craft site shell reads as intentional contrast or inconsistency
   - worth exploring: yes — the mismatch between feature quality and site shell quality may be the main craft gap

3. **how much does font choice affect the "premium" signal for this specific site?**
   - what we know: premium portfolio sites use 1-2 typefaces max; neutral sans is the default safe choice for 3d artist sites
   - what's unclear: what fonts tinamation currently uses and whether they support variable axes + optical sizing
   - worth exploring: quick audit of current font stack would answer this

4. **should sound be considered?**
   - what we know: muzli top 100 found "atmospheric sound & motion pairing" in some of the best portfolios; it creates memorable multisensory experiences
   - what's unclear: whether sound is appropriate for tinamation's target audience/context; how to implement tastefully with user control
   - worth exploring: low priority given the risk of annoying users; only if the artist's work has an audio dimension
